# M8.4.8 - Final measurement of part A (Windows, development evidence)

Raw data: [M8.4.8-final-windows.json](M8.4.8-final-windows.json), written by
`node tools/measure_engine_analysis.mjs --only scenarios --pairs 3 --synthetic <package>` and, for the stroke, the `responsiveness` phase of the same tool; rules in
`tools/engine_gates.mjs`. Same computer as M8.4.1 (Windows 11, Ryzen 7 7700X, 31 GiB, Electron 45.2.2, bundled Python 3.12.16), run from source after the
restart card M8.4.7. One unrecorded warm-up pair and three alternating pairs, so the p95 is the maximum of the samples.

p95 (maximum of the samples): (a) 286 and 924 ms against limits of 103 and 102; (b) 1,281 and 1,089 ms against 159 and 198 (one slow edit sample in each mode distorts these).
Whole-process memory peak **passes** (public 798 MiB off, 907 on, limit 1,054; synthetic 845 and 988, limit 1,101). Parity **passes** (0 mismatches against the JavaScript
reference after the interval change, the edit, the undo and the redo).

(medians 166 and 271 ms). By the decision of 15 November 2026 neither blocks the milestone gate: the fix is the tile store of part C.

Other items measured in M8.4.8:

- **Input during a brush stroke** (guarantee (4) of M8.4.4): 60 injected pointer moves while the previous stroke's analysis is on its way, public example, p95 input-to-next-frame
  15.6 ms with the engine on and 15.6 ms off (61 events each); the sections are analysed and settled afterwards. Passes (`stroke_responsiveness`).
- **Coordinator killed**: the desktop end-to-end test with the engine on kills the coordinator twice (first loss repaired by itself, second by Retry) and once more about 110 ms after an
  undo click, while the changed rows are on their way: the project keeps the undo, the program recovers, results equal the reference, the save succeeds (three consecutive runs).
- **Kill phase of the measuring tool**: after the coordinator is killed the engine is `ready` again and all six sections `ready`. Its worker-kill part found no worker to kill in three
  attempts (jobs last about 150 ms now) and reads `pass: false`; see the result of card M8.4.7.

Not measured: macOS, Linux, a clean machine, cold cache, saturated CPU, a 16 GiB computer. `smoke.mjs` was not run locally (starting its server is refused in this environment); the
`e2e` job of GitHub runs it.
