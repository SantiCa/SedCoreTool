# M8.4.18d: a package above 4 GiB through the desktop program (Windows, 20-21 Nov 2026)

Evidence: [M8.4.18d-large-package-windows.json](M8.4.18d-large-package-windows.json), written by `tools/check_large_package.mjs` (version made by
`tools/make_large_mask_version.py`). Host: Windows 11, AMD Ryzen 7 7700X, 32 GiB; commit `2f6331b`. (The record's field `electron` holds the
version of the Node inside Electron, v24.22.2; the tool now names it `electron_node`.)

| Step | Result |
|---|---|
| Synthetic tiled section | 32,768 x 57,344 pixels, 7,168 tiles of labels (65,535 objects drawn at random in every pixel), no exclusion; written with the engine's own store code in 136 s; 4,964,279,517 bytes stored |
| Package made by the page (`packageProjects`, a Chromium Blob) | 4,968,642,003 bytes, with ZIP64 end records, in 96 s |
| Store moved aside, engine restarted, package imported (`restoreFiles`) | every blob verified by the engine on import; the store then holds the same 7,174 files as the store moved aside, the manifest byte for byte identical; 64 restored blobs decompressed in Node to their names |
| Opening the imported project | **failed** after about 4 to 8 minutes of reading the tiles back: "Cannot read properties of undefined (reading 'error')" in the tool's run, "Unable to deserialize cloned data" in a second opening of the same project (with "Failed to load resource: net::ERR_UNEXPECTED" in the console); the load reported its failure and nothing was saved over the stored project |

**Verdict.** The criterion of card M8.4.18d (a package whose masks exceed 4 GiB written and restored exactly through the desktop program) is met.
Opening a section whose 7,168 tiles all hold masks is a separate failure of the reopening path (cards M8.4.18a/M8.4.29), recorded as card M8.4.36;
its cause is not known (a reply of the main process that the page could not receive, which points to memory in the page, not confirmed).
Not run: macOS and Linux; a real image of that size (the section has no source image, so it would open grey).

**Card M8.4.36 (21 Nov 2026).** The failure to open was the row histograms of the interval table (about 11 GB for this section); with them
bounded, `tools/check_large_package.mjs` passed end to end: [record](M8.4.36-large-package-windows.json) (package 4,968,642,003 bytes in 95 s,
the import and the opening with every tile in 562 s, the page at about 1 GiB).
